Already done when the vscodeClaude CBM leaf (=collective/induct/vscodeClaude=) is materialized.
Its assemble, [[bashRun:vscodeClaude-assemble.cs -i fullUpdate]], installs three things for the
invoking user, each merged into the user's files with a backup:
1. the pinned VS Code extensions, Claude Code among them (=vscode-sbom.pcs -i extsInstallPinned=);
2. VS Code to Blee, Ctrl+K Ctrl+E: a user task and key (=vscode.cs -i vscodeBleeLinkInstall=);
3. the Claude Code hooks to Blee, Stop and Notification, in =~/.claude/settings.json=
   (=vscodeClaude.cs -i hooksInstall=); only sessions started afterwards read them.
To check that a platform has them (read-only): [[bashRun:vscodeClaude-assemble.cs -i fullCheck]].

Since 2026-11-02 (blee/vscode-claude 14.1), the terms of the
[[elisp:(blee:bnsm:panel-goto "/bisos/panels/bisos-core/bisos-pip/bisos.aiActivity/ModelAndTerminology/_nodeBase_")][ModelAndTerminology]] panel:
1. *Start Blee, then* [[elisp:(b:vscode/init)][b:vscode/init]] (=partner-init= in the driver;
   [[elisp:(b:vscode/partnerShow)][partnerShow]] to check). It writes the partner file; it is run
   by hand on purpose, so a second (test) Blee never takes the role.
2. *Start =code=*, on Blee's DISPLAY. Which windows it has does not matter.
3. *In =AI-WorkPlan.org=, click =session-start= in the driver* (=|S| session-start= also submits).
   Blee takes the WorkPlan's home, its AI-Activity Root (refused when there is none), and brings
   forward the VS Code window that has it as its folder, or opens one; never replacing another
   window's folder. When sessions already run there it asks which, or a new one; otherwise a new
   conversation starts in that window, with =/bx-session-start dir= emacs= register==. Claude
   checks that its Session-Root is an AI-Activity Root, reads the import chain, reaches this Emacs
   and registers its session id. You press Enter.
4. *Work.* =Visit= (=b:vscode/fileOpen=) opens files in the home's window. =activity-reach= in a
   buffer of a sub, or of another root's AI-Activity, reaches it: native or foreign, with a warning
   when another session may be working on it. =activity-report= and =session-report= say where
   things stand.

  is started in the window of the buffer's root (=claudePrompt --folder=), and "new" says where.

- VS Code matches a folder by the spelling it was opened with (=/bxRepos/...= and its true name are
  two folders to it): =vscodeOpenFolder --window=focus= finds the open window by true name and
  passes its spelling.

  started. Not yet tried.
